Local Administrators

Accounts use administrator, operator, or read-only access. Accounts stay local during HA traffic sync. Changes apply immediately; password resets and session revocation require affected users to sign in again.

Configuration Sync

Shows whether the saved local traffic configuration matches the snapshot acknowledged by standby. Pending edits remain local in manual mode until Sync now succeeds. Unsaved form drafts are not included.

Traffic ownership

Move traffic between appliances after initial deployment. Force failover waits for the current owner to stop or be fenced; existing connections reconnect.

Initial deployment and split-brain protection

Complete the numbered steps in order. Steps 1–4 run on both appliances; steps 5–7 run on the initial primary. Packages are included in new appliance ISOs.

Deploy HA on this appliance

Save the group above on both appliances using their actual hostnames. Each action below requires your RiverLB password and, if enabled, an authenticator code. Re-enter credentials for each action; password fields clear afterward.

1. Prepare this appliance

Use the same cluster password on both appliances. Preparation creates synchronization keys and starts the restricted HA transport.

2. Verify and trust the peer

This appliance's public identity

Copy these public keys to the peer's trust fields below. Compare the host fingerprint directly in the peer's GUI before trusting it. Private keys stay on this appliance.

Copy the peer’s public identity from its HTTPS GUI into these fields. Verify the fingerprint before installing trust on each appliance.

3. Authenticate both hosts

Re-enter the shared cluster password and your RiverLB credentials, then authenticate from each appliance.

4. Start standby operation

Switch each appliance to HA standby. Standalone traffic stops and management briefly disconnects. Refresh after the service starts.

5. Create the two-appliance cluster

On the initial primary only, provision the cluster after both appliances report Standby. Traffic remains disabled until step 7.

6. Configure failover protection

Choose where the appliances run, connect to its management service, and identify each appliance. Fencing stops an unreachable peer before takeover so both appliances cannot own the VIP.

Virtual Servers

Define listeners and assign a reusable pool or inline backends.

Pools

Manage named backend sets and their balancing algorithm. Changes update every virtual server that references the pool.

Health Monitors

Create reusable TCP, HTTP, HTTPS, ICMP, UDP, DNS and TLS readiness checks. Assign a name in a pool or inline virtual server. HTTPS verifies the server against your CA PEM file.

Nodes

Reusable backend IP/service endpoints. Disabling a node prevents new connections in every referencing virtual server.

Domain Routing

Match an HTTP hostname on a virtual server and route to a reusable node. HTTPS requires TLS termination; DNS and certificate selection are configured separately.

Profiles

Select a profile type to view its defaults and custom profiles. Open an entry to view its details, or create a new profile.

HTTP Profiles

Reusable body/header limits and client keepalive settings. Clone the default http profile or create a custom profile.

Source Persistence Profiles

Reusable source address affinity and stateless source hash. Assign a profile in Virtual Servers. Records are per virtual server and reset on apply/restart.

Live persistence records

Clearing records takes effect immediately for future connections; existing sessions continue.

Cookie Persistence Profiles

Clone the built-in cookie profile or create a custom profile. Assign it independently of RiverRules on a virtual server. Save and apply commits profiles and assignments together.

RiverRules

Browse built-in rules for HTTP traffic, review their usage, and assign them to a virtual server. Copy a built-in rule set to customize it. Save and apply activates rule changes and assignments together.

Virtual Server Certificates

Import certificate chains and matching unencrypted private keys. Objects are immutable: rotate by importing with a new name, assigning it, and applying. Imports and deletion take effect immediately in the inventory.

VLANs

Assign external (clients) or internal (backends) roles to Linux adapters. Tagged VLANs create subinterfaces; untagged VLANs use existing adapters. Roles describe the network; virtual-server VLAN selections control traffic. Set return gateways for routed clients; managed replies use the address’s VLAN.

Self IPs

Static IPv4/IPv6 data-plane addresses on VLANs. Select floating self IPs in HA Configuration to assign their ownership to the active appliance.

Static Routes

Configure destination networks, gateways, VLANs and metrics in the main routing table.
